# 👋 웰컴 가이드: 팀원 여러분, 반갑습니다!

프로젝트에 합류하신 모든 팀원분께 감사의 인사를 전합니다. 우리 프로젝트가 지향하는 방향과 협업 문화를 조금 더 상세히 설명해 드릴게요. 

---

## 1. 프로젝트의 비전
우리는 단순한 투표 앱을 넘어, **"데이터에 기반한 즐거운 의사결정 경험"**을 제공하고자 합니다. 
초기에는 복잡한 기능을 다 담기보다, **"누구나 쉽게 투표를 만들고 실시간으로 결과를 확인하는 MVP(최소 기능 제품)"** 완성에 집중할 계획이에요.

## 2. '계약 중심 개발(Contract-First)'이란?
우리 팀은 코드 구현 이전에 **API 명세(Contract)**를 먼저 확정하는 방식을 사용합니다. 
- **왜 이렇게 하나요?**: 백엔드와 프론트엔드가 서로의 구현이 끝나기를 기다리지 않고, 미리 약속된 설계도에 맞춰 병렬로 개발할 수 있기 때문입니다.
- **주의사항**: `specs/api/openapi.yaml`은 우리 모두의 약속입니다. 이 내용을 변경하고 싶을 때는 꼭 팀원들과 상의를 거쳐 명세를 먼저 수정한 후 코드를 작성해 주세요.

## 3. 역할별 가이드

### 🎨 프론트엔드 담당자 (Client)
- `specs/api/openapi.yaml`을 참고하여 화면 구성에 필요한 데이터 구조를 파악해 주세요.
- OpenAPI Generator를 활용하면 직접 통신 코드를 짤 필요 없이, 서버와 대화할 수 있는 SDK를 1초 만에 얻을 수 있습니다.
- 정의된 디자인 토큰(추후 공유)을 활용해 일관성 있는 UI를 자유롭게 구현해 주세요.

### 💻 백엔드 담당자 (Server)
- 명세에 정의된 API 엔드포인트와 데이터 형식을 준수하여 서버 로직을 구현해 주세요.
- 어떤 언어나 프레임워크를 사용하든 자유롭지만, 결과물은 Docker 컨테이너로 배포 가능하도록 구성해야 합니다.
- 프론트엔드가 테스트할 수 있도록 API 문서(Swagger UI 등)를 제공하면 더욱 좋습니다.

## 4. 현재 명세(v0.0.1)에 대하여
지금 저장소에 있는 API 명세는 **중간 보고서 제출을 위해 팀장이 임의로 작성한 샘플**입니다. 
- 복잡한 소셜 로그인 대신 '닉네임 입력'으로 단순화해 둔 상태예요.
- 본격적으로 개발을 시작하기 전에 여러분의 의견을 반영하여 명세를 전면 수정하거나 확장할 예정이니, 부담 없이 검토해 보시고 자유롭게 의견 주세요!

## 5. 개발 자율성 보장 (Technical Autonomy)
우리 프로젝트의 가장 큰 특징은 **'자율성'**입니다. 
- 루트에 있는 `Makefile`은 팀 전체의 편의를 위한 '입구'일 뿐이며, 여러분의 작업을 구속하지 않습니다.
- 각자 담당하신 `implementations/` 하위 폴더 내에서는 본인이 가장 편한 방식대로 패키지 매니저(npm, yarn, gradle, pip 등)를 세팅하고 자유롭게 개발하셔도 괜찮습니다.
- 본인 폴더 내에서의 라이브러리 추가나 환경 설정은 다른 팀원의 영역에 영향을 주지 않으니 안심하고 작업해 주세요!

## 6. 우리의 협업 약속
- **작은 성공부터**: 처음부터 거대한 시스템을 만들기보다, 아주 작은 기능 하나가 실제로 돌아가게 만드는 것을 목표로 해요.
- **문서화의 습관**: 새로운 발견이나 이슈가 생기면 나중에 잊지 않도록 문서나 이슈 트래커에 기록해 주세요.
- **즐거운 소통**: 우리는 함께 배우기 위해 모였습니다. 모르는 것은 언제든 물어보고, 아는 것은 기꺼이 공유하는 문화를 만들어가요.
